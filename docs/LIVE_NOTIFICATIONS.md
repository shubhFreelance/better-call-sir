# Live dashboard notifications

The header bell is separate from email delivery history. Persisted InboxNotification rows are created in the business transaction, unique per recipient/event. Existing recipient resolution covers enquiries, assisted shortlists, arrangements, tuition, support and supporter invitations; explicit direct-enquiry, guardian review/acknowledgment, student-invitation and supporter-decision hooks cover the new hiring journey. An unregistered email cannot receive an authenticated in-app notification; the invitation appears for an existing matching account, or the student sees their linked dashboard after activation. No OTP or invitation secret appears in notification content.

GET /api/v1/inbox returns the current account's newest-first bounded history, unread total and current guardian verification/student setup/teacher draft tasks. POST /api/v1/inbox/{id}/read requires the recipient's authenticated session and CSRF token; repeated reads are safe. Foreign cursors/receipts return404. Account erasure deletes the recipient's inbox. Navigation remains subject to the destination's current consent, ownership and staff-region checks. Notification text contains generic event categories rather than private evidence or student records.

Socket.IO endpoint:/api/v1/live (addTrailingSlash:false on both peers to avoid Next redirecting the polling handshake). Same-origin cookies plus handshake auth.csrfToken authenticate connections; exact WEB_ORIGIN or an absent Origin with same-origin Fetch Metadata is required. No caller-selected rooms or account IDs. Current auth version, session revocation/expiry, student authority and staff MFA are rechecked. Socket heartbeat does not renew staff idle time. A socket only emits inbox:changed; authenticated HTTP fetch supplies data. Successful committed writes signal connected instances immediately; a2-second database watcher recovers external/multi-process changes. Reconnect re-fetches persisted state. Socket.IO HTTP long-polling transport is intentionally used through the existing Next rewrite, avoiding a separate public backend URL or unreliable Next development WebSocket upgrades. It is still a Socket.IO live connection. Polling deployments with multiple API replicas require sticky sessions; local acceptance uses one API instance. At higher connection volume replace the per-connection DB watcher with a shared transactional event broker and qualify connection/load limits.

Bell shows unread count (99+ cap), compact ivory/lavender cards, priority labels, dates, details links and read controls. Popover is non-modal, closes on outside click/Escape, restores keyboard focus and fits narrow screens. English/Hindi supported. Disconnected clients show reconnecting state and refresh every15seconds; reopening fetches current tasks. New live email alerts/reminders and live provider qualification remain separate from this increment.

Direct enquiry notification links include an owned conversation selector; GET /direct-enquiries?id=UUID retains overall counts and rejects foreign IDs. The UI opens the selected disclosure and offers All enquiries, so an older notification does not depend on the first history page.
